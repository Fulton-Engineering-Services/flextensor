    Advanced API¶

    Lower-level components for custom workflows. In most cases, use the Simplified API or OffloadManager instead.

    TensorManager provides direct control over warmup, profiling, and inference phases. See Internal States for details on how these components work together.

    TensorManager ¶

    TensorManager(device_gpu, pinned_memory, tensor_manager_load_strategy, release_tensors=True, benchmark_cls: type[TensorBenchmarkMode] = BenchmarkReplace, direct_mode=True, use_trace_tensor=False, loader_type='allocation_block_transfer', remove_layers_operations=None, rearrange_transfers=False, min_compute_transfer_gap=1, blocks=4, move_top_level_buffers_to_gpu=True, use_shm=False, enable_untraced_tensor_discovery=True, enable_module_tracker=True, enable_diagnostics: bool = False)

    Initialize TensorManager with configurable tensor loading strategy.

    PARAMETER DESCRIPTION
    device_gpu

    GPU device to use
    pinned_memory

    Whether to use pinned memory
    tensor_manager_load_strategy

    Strategy for loading tensors
    release_tensors

    Whether to release tensors after use

    DEFAULT: True

    benchmark_cls

    Benchmark class to use

    TYPE: type[TensorBenchmarkMode] DEFAULT: BenchmarkReplace

    direct_mode

    Whether to enable direct mode

    DEFAULT: True

    use_trace_tensor

    Whether to use trace tensor functionality

    DEFAULT: False

    loader_type

    Type of tensor loader to use. Options: - "strategy": Uses TensorStrategyLoader - "raw_block_transfer": Uses PreallocatedBatchTransferTensorLoader with RawBlockController - "allocation_block_transfer": Uses PreallocatedBatchTransferTensorLoader with AllocationBlockController

    DEFAULT: 'allocation_block_transfer'

    remove_layers_operations

    List of operations to remove layers from the strategy map

    DEFAULT: None

    rearrange_transfers

    Whether to enable transfer rearrangement optimization (default: True)

    DEFAULT: False

    min_compute_transfer_gap

    Minimum gap between compute and transfer layers for optimization (default: 1)

    DEFAULT: 1

    blocks

    Number of blocks to use for the block transfer loaders (default: 4)

    DEFAULT: 4

    move_top_level_buffers_to_gpu

    Whether to move top-level model buffers to GPU during warmup initialization (default: True)

    DEFAULT: True

    enable_untraced_tensor_discovery

    Whether to discover untraced tensors (e.g., FP8 weights passed to Triton kernels) using discovery strategies (default: True)

    DEFAULT: True

    enable_module_tracker

    Whether to enable ModuleTracker for manual traps when forward patching is not used (default: True)

    DEFAULT: True

    enable_diagnostics

    Whether to log diagnostic information (layer duration statistics, block assignment table) after strategy computation (default: False)

    TYPE: bool DEFAULT: False

    get_gpu_memory_usage ¶

    get_gpu_memory_usage() -> GPUMemoryUsage

    Get GPU memory usage by FlexTensor in inference mode.

    Returns the memory used by GPU transfer blocks and unmapped tensors that were moved to GPU. This method should be called after the manager has transitioned to inference mode (after warmup and profile phases).

    RETURNS DESCRIPTION
    GPUMemoryUsage

    Memory breakdown with per-component bytes and MB values. See GPUMemoryUsage for field details.

    TYPE: GPUMemoryUsage

    RAISES DESCRIPTION
    RuntimeError

    If called before inference mode is initialized (tensor_layer_loader is None)

    Examples:

    >>> tensor_manager.initialize_inference()
>>> usage = tensor_manager.get_gpu_memory_usage()
>>> print(f"GPU blocks: {usage.blocks_mb:.2f} MB")
>>> print(f"Unmapped tensors: {usage.unmapped_tensors_mb:.2f} MB")
>>> print(f"Total: {usage.total_mb:.2f} MB")

    benchmark_context ¶

    benchmark_context(iterations: int = 10) -> Any

    Create a benchmarking context that automatically integrates results into TensorManager.

    This method provides a context manager that creates a benchmark instance using the configured benchmark_cls, and automatically copies the benchmark results to the TensorManager's stats attributes upon context exit.

    PARAMETER DESCRIPTION
    iterations

    Number of benchmark iterations to perform

    TYPE: int DEFAULT: 10

    RETURNS DESCRIPTION
    Any

    Context manager that yields the benchmark instance (TensorBenchmarkMode).

    Examples:

    >>> with tensor_manager.benchmark_context() as benchmark:
...     model = {name: layer.to(torch.bfloat16) for name, layer in model.items()}
>>> # Stats are automatically integrated into tensor_manager

    run_profile_suite ¶

    run_profile_suite(callback, model=None, direct_mode=True)

    Run all three phases (warmup, profile, direct_mode) in sequence with a callback.

    This method automates the three-phase process: 1. Warmup phase: Collects initial tensor statistics 2. Profile phase: Collects detailed layer statistics with tensor loading 3. Direct mode phase: Profiles with direct tensor access (if enabled)

    PARAMETER DESCRIPTION
    callback

    Function to call for each phase. Should accept model as argument.
    model

    The model to prepare

    DEFAULT: None

    direct_mode

    Whether to enable direct mode profiling

    DEFAULT: True

    RETURNS DESCRIPTION

    The inference results

    load_profile ¶

    load_profile(profile_directory: str, model) -> None

    Load profile from directory and restore state to model.

    This method loads a saved TensorManagerState and restores it to the manager, but does NOT configure loaders or finalize the manager for inference. It only sets the internal tensor_manager_state and associates the model.

    After calling this method, you MUST call the following methods in order:

    1. initialize_warmup() - Configures tensor layer loaders via prepare_infer_load_mode() and patches the model with inference traps via prepare_final_model().

    2. initialize_profile() - Prepares the model for profiling mode. When a saved state exists, this is a no-op and returns the model as-is. However, if there are changes that require re-profiling, this method handles the profile mode setup.

    3. initialize_inference() - Finalizes the manager for inference mode and releases the internal model reference (sets self.model = None) to free memory.

    Example

    tm = TensorManager(device_gpu="cuda:0", ...) tm.load_profile("/path/to/profile", model) model = tm.initialize_warmup() # Required: configures loaders and patches model model = tm.initialize_profile() # Prepares profiling (no-op if state exists) model = tm.initialize_inference() # Releases model reference

    Now the model is ready for inference¶

    PARAMETER DESCRIPTION
    profile_directory

    Directory containing the profile.

    TYPE: str

    model

    Model to restore state to. The model should match the architecture used when the profile was originally saved.
    Note

    Future versions may add an optional parameter to automatically run finalization (initialize_warmup, initialize_profile, initialize_inference) after loading the profile.

    PreloadToDevice ¶

    PreloadToDevice(device_gpu: device, pinned_memory: bool = True, iterations: int = 10, pinned_memory_limit_mb: float | None = None)

    Bases: TensorBenchmarkMode

    Benchmark mode that immediately transfers tensors to GPU without timing measurements.

    This implementation provides a simple preloading strategy without collecting detailed benchmark statistics, suitable for scenarios where you just want tensors moved to GPU without measurement overhead.

    Initialize PreloadToDevice for simple tensor preloading.

    PARAMETER DESCRIPTION
    device_gpu

    Target GPU device for preloading

    TYPE: device

    pinned_memory

    Whether to use pinned memory for tensors (ignored in this implementation)

    TYPE: bool DEFAULT: True

    iterations

    Number of benchmark iterations (ignored in this implementation)

    TYPE: int DEFAULT: 10

    pinned_memory_limit_mb

    Maximum size of tensors that will be copied to pinned_memory

    TYPE: float | None DEFAULT: None
